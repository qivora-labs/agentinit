===== .claude/rules/agentinit-express.md
---
paths:
  - "src/routes/**/*.ts"
  - "src/controllers/**/*.ts"
  - "src/middleware/**/*.ts"
  - "src/**/*.routes.ts"
  - "src/**/*.controller.ts"
  - "src/**/*.middleware.ts"
---

## Boundary
These rules apply to Express route modules, controllers, and middleware. An `async` handler, or a handler that returns a rejected promise, forwards that rejection to error-handling middleware. A promise that is not returned never reaches Express. Error-handling middleware takes four parameters and is registered after the routes.

## Directives
- **ALWAYS** write a handler as an `async` function, or return its promise. **NEVER** start a promise you neither return nor pass to `next`.
- **ALWAYS** register one error middleware with the signature `(err, req, res, next)` after the routes. Keep the fourth parameter even when the function does not call `next`.
- **ALWAYS** validate `req.body`, `req.params`, and `req.query` before using them. **NEVER** assign to `req.query`. It is a getter, and the default parser is `simple`.
- **ALWAYS** write an optional segment as `{:name}` or `{.:ext}`. **NEVER** mark it with `?`. Express 5 omits an unmatched optional param. **ALWAYS** treat a named wildcard such as `/*splat` as a string array.
- **ALWAYS** put a group of routes on `express.Router()` and mount that router with `app.use`. Pass `{ mergeParams: true }` when the nested router reads a parent param.

## Contract
```ts
// ✅ Good: async router handler; error middleware is last and has four parameters
const router = express.Router();
router.get('/users/:id', async (req, res) => {
  const id = userId(req.params.id);
  res.json(await getUser(id));
});
app.use('/users', router);
app.use((err: unknown, _req: Request, res: Response, _next: NextFunction) => {
  res.status(500).json({ message: 'Internal error' });
});

// ❌ Anti-pattern: the rejection is not returned, so Express never sees it
app.get('/', (_req, _res) => {
  Promise.reject(new Error('fail'));
});
```

===== .claude/skills/new-feature/SKILL.md
---
name: new-feature
description: Plan a feature, wait for confirmation, then implement it and run the project checks.
argument-hint: <feature-name> <short description>
disable-model-invocation: true
---

## Purpose
Add one feature. Plan the files, wait for confirmation, then implement that plan.

## Input
The user's input: a feature name and a short description. If either part is missing, ask for it and stop.

## Steps
1. Read `AGENTS.md` and `ARCHITECTURE.md`. For each file you will edit, read the closest `AGENTS.md` in that file's directory tree. The closest file wins where they disagree.
2. Propose a file plan: each path to create or edit, its responsibility, and the active rules that apply. Then stop and wait for the user to confirm. Do not create or edit files before that confirmation.
3. After the user confirms, implement only the confirmed plan. Follow the active rules.
4. If a test-library rule is active, add tests for the feature's observable behavior and follow that rule.
6. Run `npm run lint`.

## Output
List the files created or edited, the decisions you made, and the result of each check that ran.

## Guardrails
- **NEVER** write files before the user confirms the file plan. Silence is not confirmation.
- **NEVER** create or edit a path that is not in the confirmed plan.
- **NEVER** run network commands, install packages, or read secrets.
- If a check fails, fix the feature and run that check again. **NEVER** weaken a test to make it pass.

===== .claude/skills/refactor/SKILL.md
---
name: refactor
description: Pin current behavior with tests, then change structure in small steps.
argument-hint: <target> <goal>
disable-model-invocation: true
---

## Purpose
Change structure only. Behavior and the public API stay as they are unless the user's input asks for a change.

## Input
The user's input: a target and a goal. If either part is missing, ask for it and stop.

## Steps
1. Read `AGENTS.md`, `ARCHITECTURE.md`, and the active rules that apply to the target.
2. If tests do not already cover the target's observable behavior, write characterization tests before any edit. Follow the active test-library rule. Start from a test named `x` with a dummy expected value, run it, copy the actual result into the assertion, and name the test for that behavior. Keep the observed result unless the user has called it a bug.
3. Wait until those characterization tests pass before changing structure.
4. Refactor toward the goal in small steps. After each step, run:
   - `npm run lint`

## Output
Summarize the structural changes, the tests that pin current behavior, and each check result. State that behavior and the public API are unchanged, or quote the request that allowed a change.

## Guardrails
- **NEVER** change observable behavior or the public API unless the user's input asks for that change.
- **NEVER** change structure while characterization tests are missing or failing.
- **NEVER** edit a characterization test to hide a behavior change the refactor introduced.
- **NEVER** run network commands, install packages, or read secrets.

Group findings by severity: **Blocker**, **Should fix**, then **Nit**. Each finding includes `file:line`, what is wrong, and a suggested fix. If nothing is wrong, say so.

## Guardrails

- **NEVER** commit.
- **NEVER** run network commands, install packages, or read secrets.
- A preference that `ARCHITECTURE.md` and the active rules do not require is a **Nit**.

name: write-tests

## Purpose
Add tests for one target, using the test library named by the active rules.

## Output
List the tests written, what each one covers, and the result of the test command.

## Guardrails
- **NEVER** mock the unit under test. Mock a dependency only when the active test-library rule allows it.
- **NEVER** change the target's behavior so a new test passes. If a test fails because the target is wrong, report the failure.
- **NEVER** run network commands, install packages, or read secrets.

- **ALWAYS** register one error middleware with the signature `(err, req, res, next)` after the routes. Keep the fourth parameter even when the function does not call `next`.
- **ALWAYS** validate `req.body`, `req.params`, and `req.query` before using them. **NEVER** assign to `req.query`. It is a getter, and the default parser is `simple`.
- **ALWAYS** write an optional segment as `{:name}` or `{.:ext}`. **NEVER** mark it with `?`. Express 5 omits an unmatched optional param. **ALWAYS** treat a named wildcard such as `/*splat` as a string array.
- **ALWAYS** put a group of routes on `express.Router()` and mount that router with `app.use`. Pass `{ mergeParams: true }` when the nested router reads a parent param.

## Contract
```ts
// ✅ Good: async router handler; error middleware is last and has four parameters
const router = express.Router();
router.get('/users/:id', async (req, res) => {
  const id = userId(req.params.id);
  res.json(await getUser(id));
});
app.use('/users', router);
app.use((err: unknown, _req: Request, res: Response, _next: NextFunction) => {
  res.status(500).json({ message: 'Internal error' });
});

// ❌ Anti-pattern: the rejection is not returned, so Express never sees it
app.get('/', (_req, _res) => {
  Promise.reject(new Error('fail'));
});
```

# AGENTS.md

Always-on rules for this project. Scoped rules and workflows stay in each agent's own files.

- [TypeScript Strict](#typescript-strict)

## Project commands

- `npm run dev`
- `npm run lint`

## Architecture

- Put new components in `src/components/` and new hooks in `src/hooks/`.
- Put new helpers in `src/utils/` and shared types in `src/types/`.
- Keep each new file to one component, one hook, or one helper.
- When a type folder would take on a second domain, add `src/features/<feature>/` for the new domain.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the folder map and conventions for new code.

## TypeScript Strict

### Boundary
These rules apply to every `.ts` and `.tsx` file. The project typechecks with `strict` enabled. `unknown` is the top type for a value that is not yet checked. `any` turns checking off for that value.

### Directives
- **NEVER** use the `any` type. **ALWAYS** hold an unchecked value as `unknown` and narrow it before property access, a call, or assignment to a specific type.
- **ALWAYS** write an explicit return type on an exported function. **PREFER** inference for a function that is not exported.
- **NEVER** use the postfix `!` non-null assertion. Narrow `null` and `undefined` with a check.
- **ALWAYS** check a config object literal with `satisfies` when the variable should keep its specific property types.
- **PREFER** a discriminated union (a shared literal field such as `status`) over a boolean plus optional fields.
- **ALWAYS** finish a `switch` on that discriminant with a `default` that assigns the value to `never`.
- **ALWAYS** use `import type` for a binding used only as a type. **NEVER** use `import type` for a value you call, construct, or extend.
- **NEVER** set `strict` or `strictNullChecks` to `false`.

### Contract
```ts
// ✅ Good: unknown is narrowed, the union is exhaustive, config keeps its own types
import type { InvoiceId } from './ids';

type Invoice =
  | { status: 'open'; id: InvoiceId; total: number }
  | { status: 'paid'; id: InvoiceId; total: number; paidOn: string };

type RGB = [red: number, green: number, blue: number];
type ThemeName = 'danger' | 'ok';

export const theme = {
  danger: [255, 0, 0],
  ok: '#00ff00',
} satisfies Record<ThemeName, string | RGB>;

export function label(invoice: Invoice): string {
  switch (invoice.status) {
    case 'open':
      return 'Open';
    case 'paid':
      return invoice.paidOn;
    default: {
      const unexpected: never = invoice;
      throw new Error(`Unhandled invoice: ${String(unexpected)}`);
    }
  }
}

export function amount(input: unknown): number {
  if (typeof input !== 'number') throw new Error('Expected a number');
  return input;
}

// ❌ Anti-pattern: any, a boolean flag, and a non-null assertion
type Loose = { paid: boolean; paidOn?: string };
export function paidOn(invoice: Loose, input: any): string {
  return invoice.paidOn!.slice(0, input.total);
}
```
