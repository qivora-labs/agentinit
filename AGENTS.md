# AGENTS.md — Working on `@agentinit/cli`

This file is for AI coding agents (and humans) developing this repository. It is hand-written; it is **not** output generated by the CLI.

## Source of Truth
- **What to build:** [`docs/PRD.md`](docs/PRD.md). Never contradict it silently.
- **What to build next:** [`docs/tasks/`](docs/tasks/README.md). Work on exactly one task per session.
- **Where code goes:** [`ARCHITECTURE.md`](ARCHITECTURE.md) — folder map, dependency rules, which modules may touch disk.
- If the PRD and a task disagree, or the PRD is silent on something you need, **stop and ask** instead of inventing behavior. If the user decides, update the PRD in the same change.

## Commands
Repo-only scripts (common `build` / `dev` / `lint` / `test` / `typecheck` live in the managed block below):
```bash
pnpm check:package    # publint
pnpm registry:check   # registry content checks
pnpm smoke            # packed-tarball smoke test
```
Before finishing any task, `pnpm lint && pnpm typecheck && pnpm test && pnpm build` must pass.

## Core Conventions
- TypeScript strict, ESM only, Node `^22.18.0 || ^24.11.0 || >=26.0.0`. Named exports only; no default exports.
- Respect the purity boundaries in `ARCHITECTURE.md`: `registry/resolve.ts`, `plan/`, and `targets/` never touch disk, `process`, prompts, or the clock.
- User-facing errors are `AgentInitError` with an exit code, readable without a stack trace.
- Keep dependencies to those listed in PRD §4.2. Ask before adding a runtime dependency.
- Every task adds or updates tests for the behavior it introduces.
- Comments explain constraints the code can't show, not what the next line does.

## Workflows
Reusable procedures live in `docs/workflows/` and are exposed as slash commands (`.claude/skills/`; Cursor loads these too):
- `/implement-task <id>` — implement one task from `docs/tasks/`.
- `/review-task <id>` — read-only review of a finished task.
- `/write-fragment <id>` — author or revise a registry fragment.
- `/commit-changes` — commit the working tree (conventional commits, no co-author trailer, no push).

Agents without slash commands can open the matching file in `docs/workflows/` and follow it.

## TypeScript Strict

### Boundary
These rules apply to every `.ts` and `.tsx` file. The project typechecks with `strict` enabled. `unknown` is the top type for a value that is not yet checked. `any` turns checking off for that value.

### Directives
- **NEVER** use the `any` type. **ALWAYS** hold an unchecked value as `unknown` and narrow it before property access, a call, or assignment to a specific type.
- **ALWAYS** write an explicit return type on every exported function, including small helpers (`parse*`, `safeParse` wrappers, and schema mappers). **Exception:** React components and framework entry files (`page`, `layout`, route handlers) may omit a return type. **PREFER** inference for a function that is not exported.
- **NEVER** use the postfix `!` non-null assertion. Narrow `null` and `undefined` with a check.
- **ALWAYS** check a config object literal with `satisfies` when the variable should keep its specific property types.
- **PREFER** a discriminated union (a shared literal field such as `status`) over a boolean plus optional fields.
- **ALWAYS** finish a `switch` on that discriminant with a `default` that assigns the value to `never`.
- **ALWAYS** use `import type` for a binding used only as a type. **NEVER** use `import type` for a value you call, construct, or extend.
- **NEVER** set `strict` or `strictNullChecks` to `false`.

### Contract
```ts
// ✅ Good: unknown is narrowed, exports name their return types, config keeps its own types
import type { InvoiceId } from './ids';

type Invoice =
  | { status: 'open'; id: InvoiceId; total: number }
  | { status: 'paid'; id: InvoiceId; total: number; paidOn: string };

type ParseAmountResult =
  | { success: true; data: number }
  | { success: false; error: string };

type RGB = [red: number, green: number, blue: number];
type ThemeName = 'danger' | 'ok';

export const theme = {
  danger: [255, 0, 0],
  ok: '#00ff00',
} satisfies Record<ThemeName, string | RGB>;

export function parseAmount(input: unknown): ParseAmountResult {
  if (typeof input !== 'number') return { success: false, error: 'Expected a number' };
  return { success: true, data: input };
}

export function label(invoice: Invoice): string {
  switch (invoice.status) {
    case 'open':
      return 'Open';
    case 'paid':
      return invoice.paidOn;
    default: {
      const unexpected: never = invoice;
      throw new Error(`Unhandled invoice: ${String(unexpected)}`);
    }
  }
}

// ❌ Anti-pattern: any, a boolean flag, a non-null assertion, and a missing export return type
type Loose = { paid: boolean; paidOn?: string };
export function paidOn(invoice: Loose, input: any) {
  return invoice.paidOn!.slice(0, input.total);
}
```
