# T49 · Version-Aware `doctor`: Rule Updates Don't Fail CI

| Milestone | Depends on | Unblocks | PRD | Size |
| :--- | :--- | :--- | :--- | :--- |
| M9 — 0.1.1 patch | — | T50 | §6.2, §6.5 | M |

## Goal
A new agentinit release that changes rule text no longer turns users' CI red. Drift that comes from a different CLI version is a warning. Drift that comes from the project itself stays an error.

## Context
- `doctor` reports an `update` change (an owned, unedited file whose content differs from what the running CLI would generate) as `outdated`, with severity `error`. See `drifted(change, 'outdated', …)` and `SEVERITY_FOR_KIND` in `src/doctor/checks.ts`.
- Until PR #54, the README's CI example ran `npx --yes @agentinit/cli doctor` unpinned. CI therefore picks up every new release, and the first release that edits any fragment would fail every unpinned user's build with no change in their repository. PR #54 pins the example to `0.1.0` as a stopgap.
- The manifest already records `cliVersion` (written in `src/commands/init.ts`). `doctor` doesn't use it.
- The dogfood manifest has `cliVersion: "0.0.0"`. Released manifests have `0.1.0`.

## Scope
1. **Inputs** (`src/commands/doctor.ts`): pass the running CLI version (from `package.json`, as `init.ts` does) and `manifest.cliVersion` into `collectDoctorIssues`. `doctor/checks.ts` stays pure.
2. **New issue kind `rules-update`** (`src/doctor/checks.ts`), severity **warning**, under the `managed-files` check:
   - When the two versions differ, every `update` change becomes `rules-update` instead of `outdated`.
   - Running CLI newer than the manifest: "`<path>` was generated by agentinit 0.1.0. agentinit 0.1.1 generates different rules." Fix: `npx @agentinit/cli@0.1.1 init`.
   - Running CLI older than the manifest: "`<path>` was generated by a newer agentinit (0.2.0)." Fix: "Run doctor with `@agentinit/cli@0.2.0` or newer."
   - A `cliVersion` that isn't valid semver counts as "different".
   - When the versions are equal, `outdated` stays an error, exactly as today.
3. **Unchanged checks**: `edited`, `missing`, `unmanaged`, `stale`, `unselected`, `package-removed`, and `unsupported-version` keep their severity whatever the versions.
4. **TTY and JSON output**: the managed-files row shows the warning icon when its only issues are `rules-update`. `--json` reports `"kind": "rules-update", "severity": "warning"`, and `ok` stays `true`.
5. **README** (`doctor` in CI): from 0.1.1, an unpinned `npx @agentinit/cli doctor` warns instead of failing on rule updates. Pinning stays recommended for reproducible CI. Keep the upgrade steps from PR #54.
6. **PRD** §6.5: add `rules-update` to the severity table, with one sentence on the trade-off below.
7. Add a `patch` changeset describing the user-visible change.

## Out of scope
- Rewriting the manifest's `cliVersion` when `init` changes nothing (see Notes).
- Unknown manifest keys and refusing older CLIs (T50).
- A `--strict` flag that promotes warnings to errors (backlog P2.5).

## Implementation notes
- **Accepted trade-off:** while the versions differ, `doctor` can't tell a rule change from a project change that alters generated text (for example, a new `test` script changing the commands in `AGENTS.md`). Both are reported as `rules-update` warnings until someone runs `init` with the current CLI. Package-level checks still catch added or removed dependencies as errors.
- Compare versions with `semver`, which is already a dependency. `checks.ts` may import it, because it's pure.
- Add `rules-update` to `DOCTOR_ISSUE_KINDS`, `CHECK_FOR_KIND`, `GROUP_TITLE`, and `SEVERITY_FOR_KIND`. The `never` switch forces this.
- Update `tests/__snapshots__/e2e/screens/doctor-*` with `pnpm test:screens` if TTY output changes.

## Acceptance criteria
- [ ] Simulated older output: on an initialized fixture, change one generated rule file, set its manifest `sha256` to the new content, and set `cliVersion` to `0.0.9`. `doctor` exits `0`, shows a `rules-update` warning, and `--json` has `ok: true`.
- [ ] The same setup with `cliVersion` equal to the running version exits `2` with `outdated`.
- [ ] A hand-edited generated file exits `2` with `edited`, whatever `cliVersion` says.
- [ ] `cliVersion: "0.2.0"` with a running `0.1.1` gives the "generated by a newer agentinit" message.
- [ ] After `init --yes` with the current CLI, `doctor` reports no issues.
- [ ] A `patch` changeset exists. README and PRD §6.5 updated.

## Notes
- When a newer CLI's `init` changes nothing, the manifest keeps its older `cliVersion`. That's harmless: with no `update` changes there is nothing to report, and the next `init` that writes also refreshes `cliVersion`.
