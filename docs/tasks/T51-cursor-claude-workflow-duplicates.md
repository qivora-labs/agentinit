# T51 · No Duplicate Workflows When Cursor and Claude Code Are Both Selected

| Milestone | Depends on | Unblocks | PRD | Size |

## Goal
A project that selects both Cursor and Claude Code (the default when no agent config exists) sees each workflow once in Cursor's slash menu, not twice.

## Context
- The Cursor target writes workflows to `.cursor/commands/<id>.md` (`src/targets/cursor.ts`). The Claude target writes `.claude/skills/<id>/SKILL.md`.
- T48 Notes (2026-11-07) report that Cursor's commands docs now redirect to skills (`/migrate-to-skills`, Cursor 2.4+), and that Cursor also loads `.claude/skills/`. With both agents selected, Cursor may list `/new-feature` and the other workflows twice.
- `docs/compatibility.md` sets the Cursor minimum at 1.6 because of commands.
- T41's `src/owned-paths.ts` lists the owned workflow paths per target.

## Decisions (owner, before starting)
First verify the current behavior against Cursor's official docs and changelog, and record the URLs under **Notes**: which folders Cursor loads skills from, from which version, and whether commands are deprecated. Then choose:
- **A** — When Claude Code is selected, the Cursor target writes no workflow files; Cursor picks them up from `.claude/skills/`. When Claude isn't selected, keep `.cursor/commands/`.
- **B** — The Cursor target writes `.cursor/skills/<id>/SKILL.md` instead of commands, and skips them when Claude Code is selected. This raises the Cursor minimum to the skills version.
- **C** — Keep the current output and document the duplicates as a known limitation.

Recommended: **B** if the docs confirm both skill folders; otherwise **A**.

## Scope
For decision A or B:
1. **Target** (`src/targets/cursor.ts`): emit workflows according to the decision. The adapter receives the selected agents through its existing context. It must not import the Claude adapter.
2. **Owned paths** (`src/owned-paths.ts`): add `.cursor/skills/<id>/SKILL.md` if B. Keep `.cursor/commands/<id>.md` owned, so files from 0.1.0 are cleaned up.
3. **Re-runs**: unedited `.cursor/commands/*` files from 0.1.0 become stale and are deleted through the existing stale path. Edited ones are reported, as today.
4. **Report and review card**: the Cursor file counts reflect the new output. Next steps still suggest `/new-feature` when workflows exist.
5. **Docs**: `docs/compatibility.md` (Cursor minimum and sources), README "What we write" table, PRD §5.2 output matrix and §5.4.
6. Update target, plan, and e2e snapshots.
7. Add a `patch` changeset that says workflow files move and that old `.cursor/commands` files are removed on the next `init`.

For decision C: README known limitations, PRD §13, and the changeset, only.

## Out of scope
- Windsurf / Devin Desktop moving workflows to skills (backlog).
- Per-workflow selection.
